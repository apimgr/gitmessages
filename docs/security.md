# Security and privacy

Git Messages serves static curated data and never accepts user-submitted commit messages or conventions. It has no user accounts or administrative web UI. Anonymous owner tokens and the operator token protect the operations defined by AI.md; configured contact and security-report forms accept limited report content under the documented privacy and retention rules. Builder requests are stateless.

HTTP requests are subject to input validation, request body limits, per-client rate limiting, configured CORS, and browser security headers. The MCP endpoint additionally requires JSON-RPC protocol/header agreement and rejects untrusted `Origin` values; the wildcard CORS default does not authorize MCP origins. MCP exposes only public reads and stateless message building. The service does not query third-party content or data providers. When Tor is available, the server runs its own dedicated Tor process for onion access; I2P access is optional and uses a local provider. Operators should terminate clearnet TLS at a trusted reverse proxy before public deployment and restrict network access as appropriate.

Security reporting instructions are available at `/server/security`, mirrored at `/api/v1/server/security`, and published as `/.well-known/security.txt`. The server contact form accepts coordinated vulnerability reports when enabled. GitHub private vulnerability reporting remains the repository's primary source-code reporting channel; do not publish exploit details in a public issue.

The health endpoint reports service version and the availability state of configured overlay services. It may include public onion or I2P hostnames, but never private keys or control credentials. Security reports can be filed through `/server/security` or the configured GitHub private vulnerability reporting channel; the exact server reporting behavior is documented in the Security and Contact pages.
