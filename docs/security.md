# Security and privacy

Git Messages serves static curated data and never accepts user-submitted commit messages or conventions. It has no user accounts or administrative web UI. Anonymous owner tokens and the operator token protect the operations defined by AI.md; configured contact and security-report forms accept limited report content under the documented privacy and retention rules. Builder requests are stateless.

HTTP requests are subject to input validation, request body limits, per-client rate limiting, configured CORS, and browser security headers. The MCP endpoint additionally requires JSON-RPC protocol/header agreement and rejects untrusted `Origin` values; the wildcard CORS default does not authorize MCP origins. MCP exposes only public reads and stateless message building. The service does not query third-party content or data providers. When Tor is available, the server runs its own dedicated Tor process for onion access; I2P access is optional and uses a local provider. Operators should terminate clearnet TLS at a trusted reverse proxy before public deployment and restrict network access as appropriate.

Security reporting instructions are available at `/server/security`, mirrored at `/api/v1/server/security`, and published as `/.well-known/security.txt`. Researchers should read the published `Contact`, `Policy`, `Expires`, and `Preferred-Languages` fields, then use the listed reporting channel. The security overview also links to `/server/security/policy` and provides a rotating `security_id` for the coordinated report form at `/server/contact?security_id=…`. The form is available only when `server.pages.contact.enabled` is true and accepts coordinated vulnerability reports, abuse reports, DMCA notices, and privacy requests; it is not a general support channel. GitHub private vulnerability reporting remains the repository's primary source-code reporting channel; do not publish exploit details in a public issue.

The public security endpoints are `/.well-known/security.txt`, the optional `/.well-known/pgp-key.asc`, `/.well-known/llms.txt`, `/server/security`, `/server/security/policy`, `/server/security/thanks`, `/server/contact`, `/server/dpo`, `/server/healthz`, and `/api/v1/server/healthz`. `/.well-known/pgp-key.asc` is available only when public key publication is enabled. Unknown `/.well-known/*` paths return `404`; the server does not provide other discovery documents unless a feature explicitly enables them.

The API mirrors security metadata at `/api/v1/server/security`, `/api/v1/server/security/policy`, `/api/v1/server/security/thanks`, and `/api/v1/server/dpo`. These public metadata routes do not reveal report contents, contact recipients, private keys, or credentials. The health endpoint reports service version and configured overlay availability, and may include public onion or I2P hostnames. The optional `/healthz` alias is disabled by default; `/api/healthz` is the direct unversioned API alias.
