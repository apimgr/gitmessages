# Security and privacy

Git Messages serves static curated data and never accepts user-submitted commit messages or conventions. It has no user accounts or administrative web UI. Anonymous owner tokens and the operator token protect the operations defined by AI.md; configured contact and security-report forms accept limited report content under the documented privacy and retention rules. Builder requests are stateless.

HTTP requests are subject to input validation, request body limits, per-client rate limiting, configured CORS, and browser security headers. The MCP endpoint additionally requires JSON-RPC protocol/header agreement and rejects untrusted `Origin` values; the wildcard CORS default does not authorize MCP origins. MCP exposes only public reads and stateless message building. The service does not query third-party content providers for catalog data. It downloads operational GeoIP, blocklist, CVE, and optionally Trivy security datasets as required by AI.md; failed updates preserve the last valid dataset and are reported through health checks. When Tor is available, the server runs its own dedicated Tor process for onion access; I2P access is optional and uses a local provider. Operators should terminate clearnet TLS at a trusted reverse proxy before public deployment and restrict network access as appropriate.

The request security order is allowlist, IP and domain blocklists, rate limiting, then GeoIP country checks. An allowlisted client bypasses those four checks but still reaches route authentication and authorization. Blocklists use the built-in FireHOL IP feed and optional operator feeds; domain feeds check the request `Origin` or, when absent, `Referer`, submitted email domains, and submitted URLs. GeoIP only denies configured countries: private and internal addresses are skipped, and missing data or lookup failures fail open.

Security reporting instructions are available at `/server/security`, mirrored at `/api/{api_version}/server/security`, and published as `/.well-known/security.txt`. Researchers should read the published `Contact`, `Policy`, `Expires`, and `Preferred-Languages` fields, then use the listed reporting channel. The security overview also links to `/server/security/policy` and provides a rotating `security_id` for the coordinated report form at `/server/contact?security_id=…`. The form is available only when `server.pages.contact.enabled` is true and accepts coordinated vulnerability reports, abuse reports, DMCA notices, and privacy requests; it is not a general support channel. GitHub private vulnerability reporting remains the repository's primary source-code reporting channel; do not publish exploit details in a public issue.

The public security and status endpoints are `/.well-known/security.txt`, the optional `/.well-known/pgp-key.asc`, `/.well-known/llms.txt`, `/server/security`, `/server/security/policy`, `/server/security/thanks`, `/server/contact`, `/server/dpo`, `/server/healthz`, `/api/{api_version}/server/healthz`, and `/api/healthz`. The `/healthz` alias directly serves the health handler when `server.healthz.root.enabled` is true; it is disabled by default. `/.well-known/pgp-key.asc` is available only when public key publication is enabled. Unknown `/.well-known/*` paths return `404`; the server does not provide other discovery documents unless a feature explicitly enables them.

The API mirrors security metadata at `/api/{api_version}/server/security`, `/api/{api_version}/server/security/policy`, `/api/{api_version}/server/security/thanks`, and `/api/{api_version}/server/dpo`. These public metadata routes do not reveal report contents, contact recipients, private keys, or credentials. The health endpoint reports service version and configured overlay availability, and may include public onion or I2P hostnames. The optional `/healthz` alias is disabled by default; `/api/healthz` is the direct unversioned API alias.
