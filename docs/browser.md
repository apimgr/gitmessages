# Browser application

The site uses server-rendered HTML and remains usable without JavaScript. Pages are responsive, support auto, light, and dark themes, and provide eight embedded languages: English, Spanish, French, German, Italian, Arabic, Chinese, and Japanese. Dark is the default theme. The header theme form cycles dark → light → auto → dark and saves the choice in a one-year, same-site cookie. The `auto` theme follows the operating system preference. Theme and language cookies are readable by the server and are not HTTP-only. Choose a language in Preferences or with `?lang=CODE`; without a saved selection, the site negotiates the browser's `Accept-Language` header and falls back to English. Arabic pages use right-to-left layout. Locale JSON is served from the same embedded files at `/locales/{lang}.json`.

On small screens, the hamburger opens a slide-in navigation drawer. The checkbox, drawer, close control, and scrim work without JavaScript; the Preferences link and theme toggle stay in the header. The drawer follows the page direction, so it opens from the inline end in both left-to-right and right-to-left locales.

- `/` introduces the product.
- `/types` lists all supported commit types and examples.
- `/templates` lists reusable feature, bug-fix, release, hotfix, and documentation templates.
- `/builder` accepts a type, optional scope, description, body, convention, and breaking-change marker. The server validates and renders the resulting message.
- `/server/about`, `/server/help`, `/server/healthz`, `/server/privacy`, `/server/terms`, and `/server/security` provide service information and reporting guidance. `/server/contact` handles the configured contact and security-report flows; `/server/dpo`, `/server/security/policy`, and `/server/security/thanks` expose the related public information. Their API mirrors are under `/api/{api_version}/server/` where defined.
- `/server/preferences` lets visitors save theme, language, and consent choices in browser cookies. `/api/{api_version}/server/preferences` reports the current request's preferences.
- `/server/preferences/sync` exports portable preferences as a URL and code, then imports them on another device. Consent and credential cookies are not included. The API mirrors are `/api/{api_version}/server/preferences/sync` and `/api/{api_version}/server/preferences/sync/import`.
- `/server/preferences/tokens` manages the anonymous owner's tokens without requiring a JavaScript client. Primary-token revocation displays the linked-token and resource counts, requires the last four token characters, then deletes the owner and its tokens and clears this browser's saved token. `/api/{api_version}/server/preferences/tokens/*` provides its API mirror.
- `/server/metrics[/{service}]` exposes internal Prometheus, Grafana, and Loki-compatible endpoints when enabled; each service requires its own Bearer token. See [Metrics](metrics.md).
- `/server/help/mcp` explains the Bearer-authenticated MCP connection and tools; `/api/{api_version}/server/help/mcp` mirrors that help data.
- `/.well-known/security.txt` publishes the security reporting contact, supported languages, expiry, canonical URL, and policy link.
- `/.well-known/llms.txt` and `/llms.txt` publish discovery information for automated clients. `/.well-known/pgp-key.asc` is available when public key publication is enabled.
- `/robots.txt` publishes the configured crawler allow/deny rules and a request-specific absolute `Sitemap:` URL. `/sitemap.xml` lists the public HTML pages, including the API documentation pages, that pass those same rules; API endpoints, feeds, and the contact form are excluded. Both accept `GET` and `HEAD`; robots.txt is cached for five minutes, while the sitemap provides ETag and Last-Modified validators.
- `/feed.xml` is an Atom 1.0 feed and `/rss.xml` is RSS 2.0. Both currently return valid feeds with zero entries because this project has no public item resource with per-item pages and creation timestamps. These endpoints accept `GET` and `HEAD`; feeds include ETag and Last-Modified validators and are cached for five minutes.
- HTML pages include route-aware title and description metadata, a canonical URL, JSON-LD site metadata, and OpenGraph/Twitter card tags when enabled. Operators can set branding, canonical URLs, and social metadata in `yaml.d/branding.yml`; configured search-engine verification values and validated custom meta tags are rendered in the page head.
- Public HTML pages default to `index,follow`; other routes default to `noindex,nofollow`. The response also carries `X-Robots-Tag: noindex, nofollow` for non-indexable routes. Setting `server.seo.noindex: true` applies that directive to every route while leaving the sitemap and feeds available.
- `/manifest.json`, `/icon.svg`, the generated PNG icon set under `/static/icons/`, the iOS splash images under `/static/splash/`, `/offline.html`, and `/sw.js` provide installable PWA metadata and the offline fallback. The manifest includes standard and maskable icons from 72px through 512px, plus browser favicon and Apple touch sizes.

The service worker precaches the version-stamped stylesheet, theme, GraphiQL and Swagger UI vendor assets and startup scripts, manifest, standard icons, and offline page. It caches successful visits to public reference and server information pages. Navigations try the network first with an eight-second timeout, then use a cached page or an offline response. Static assets use the cache first. The cache is limited to 50 MiB, entries expire after seven days, and activation removes older build caches. API requests and non-GET requests pass through without interception; no requests are queued for later. The commit builder and APIs therefore require a network connection.

API responses include the current `X-Build` stamp. If an open page detects a newer build, it reloads after the current request unless a form has unsaved changes; then it shows the update prompt so the visitor chooses when to reload. A build-stamp mismatch on a top-level document navigation also sends `Clear-Site-Data: "cache", "storage"` to remove stale caches without clearing cookies. When a new worker is ready, the page displays an update prompt. Choosing **Update now** tells the waiting worker to activate and reloads the page when control changes, with a five-second fallback reload. The first worker installation activates automatically. The page also shows an offline status indicator when the browser reports no network connection. The site remains usable without JavaScript or a service worker.

The install control appears when the browser provides `beforeinstallprompt`; installed standalone windows do not show it. On iOS Safari, the page instead provides manual **Add to Home Screen** instructions. The manifest provides standard and maskable PNG icon sizes, and the page includes an Apple touch icon, startup images, and web-app metadata.

Unknown browser routes return a themed 404 page with navigation back to the site. Text clients receive a plain-text not-found response, and API routes keep their documented JSON or text error formats.
